Methods and filters: templates can call a view's methods with arguments, applications can add their own filters, and both are checked at startup.

## Highlights

- **Methods with arguments.** A schema declares `method("options", &[Kind::Text], Kind::list(Kind::Text))`; a template writes `{% for s in product.variations.options("size") %}`. The compiler checks the argument count and kinds; `View::call` answers with a borrowed value or text built for the call.
- **Application filters.** `Builder::filter("money", &[Kind::Text], Kind::Text, |v, args| ...)` adds `{{ order.cents | money("EUR") }}`, checked like a built-in.
- **New built-in filters:** `truncate(n)`, `join(sep)`, `first`, `last`, `replace(from, to)`, `date(format)` for Unix times, and `number` for digit grouping.
- **`{% set name = expr %}`** names a value until the end of its block.
