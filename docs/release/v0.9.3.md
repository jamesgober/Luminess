A security release, and faster rendering. Every user of an earlier version should upgrade: there are no API changes, and correct themes need no changes.

## Security

- Fixed URL scheme checking for URLs built from several values, or from a value and the template's own text, and for whitespace before a value in a URL attribute.
- Comment and raw-text element parsing now follows the HTML specification.
- The JavaScript tracker reads HTML-like comments, line breaks in strings, and `/` after `++` and `--` as browsers do.
- A long chain of `and`, `or`, or filters is a compile error instead of exhausting the stack; compiling many includes is linear in time and bounded at 16 MiB of text per template.
- A template compiled against a schema its engine's view type does not answer can no longer be rendered by name, only included.

A few templates that were accepted before are now refused at startup, each with a message saying what to change: a literal `:` or `&` right after an output and before a URL's first `/`, `?`, or `#`, and a JavaScript string that runs past a line break.

## Faster

Three alternating runs of 0.9.2 and 0.9.3 on the same quiet machine:

| Case | 0.9.2 | 0.9.3 |
|---|---|---|
| typical page | 5.1 to 5.3 µs | 3.6 to 4.2 µs |
| typical page into a new `String` | 5.8 to 6.7 µs | 4.1 to 4.7 µs |
| a plain field, dispatch | about 12.5 ns | about 6 ns |
| a condition on a field | about 16 ns | about 6 ns |
| an integer | about 16 ns | about 8 ns |
| `escape::html`, clean text | 8 GB/s | 12.5 GB/s |

How: plain field outputs and conditions read their path directly instead of going through the general evaluator; a literal and the output after it are one node; text, URLs, and integers have direct write paths; integers are written two digits at a time; the output buffer is reserved once; the HTML escaper skips sixteen bytes at a time on safe text.

On the same page Askama takes about 2 µs, Tera about 16, and MiniJinja about 26. `docs/PERFORMANCE.md` has the details, including what was tried and dropped.

## Same output, apart from the fixes

`equivalence/` checks this release against the published 0.9.2: random templates (both must agree on compile errors too), structured templates that all compile, and a full page, 4,000 cases each. The structured templates and the full page match byte for byte; random templates may differ only where the security fixes apply, and there no `javascript:` URL may be written. The `same_output` fuzz target does the same on any input; all three fuzz targets ran for an hour on this release.
