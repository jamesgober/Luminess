Scripts and styles: values can now go into JavaScript and CSS, escaped for exactly where they sit.

## Highlights

- **JavaScript.** In a `<script>` element or an `on...` attribute, a value in code becomes a complete literal: text as a double-quoted string, numbers, `true`/`false`, and absent values as `null`. Inside a string or template literal, only its content is written, with quotes, backslashes, `<`, `>`, `&`, `$`, braces, and line breaks escaped. The compiler follows strings, template literals (including `${}`), comments, and regular expressions.
- **CSS.** In a `<style>` element or a `style` attribute, a value in code passes when it holds only letters, digits, spaces, and `# % . , - _` (colors, lengths, names), and becomes `blocked` otherwise. Inside a CSS string every other character is hex-escaped.
- **More refused at compile time:** output in a JavaScript comment or regular expression, right after `$` in a template literal, in a CSS comment, and in an `on...` or `style` attribute that uses character references. A template that ends inside a tag, attribute, comment, script, or style is an error.
- New escapers in `luminess::escape`: `js_string`, `js_quoted`, `css`, `css_value_allowed`.

## Checks

12 property tests (2,000 cases each) and both fuzz targets cover the new escapers. The typical-page benchmark, now with a script block, stays near 9 µs.
