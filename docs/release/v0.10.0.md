A simpler API: one-line loading and rendering, one error type, and plain names; and the rest of the hardening begun in 0.9.3. Template syntax is unchanged, and rendering is as fast as in 0.9.3 or faster. This release breaks the 0.9 API; the table below maps every change.

## Hardening

- A value is written as markup only where the schema declared it `html`; one declared text is escaped even when a view or filter answers markup.
- `Html` holds the items of a `list(html)` field; `view!` refuses a list of plain strings there.
- Refused at compile time: output in SVG animation values, right after `<` in a raw-text element other than a script, and in a script the HTML parser reads as double-escaped.
- With the `web-net` feature, a render stops at web-net's output budget instead of building the whole page first.
- Text comparisons and `set` reads copy nothing; calls with up to four arguments allocate nothing.

## The common case

```rust
use luminess::Engine;

struct Page { title: String }
luminess::view!(Page as "page" { title: text });

let engine = Engine::<Page>::from_dir("themes/default")?;      // every .html file below it
let html = engine.render("home", &Page { title: "Hi".into() })?;
engine.reload_dir("themes/default")?;                          // on error the running theme stays
```

One template: `Template::<Page>::new(source)?.render(&page)?`. One render, compiled on the spot: `luminess::render(source, &page)?`. Every call returns `luminess::Error`, so `?` works throughout.

## Migrating from 0.9

| 0.9 | 0.10 |
|---|---|
| `Engine::<V>::builder().directory(dir, "html")?.build()?` | `Engine::<V>::from_dir(dir)?` |
| `Builder::directory(dir, "html")` (an `io::Error`) | `Builder::directory(dir)` (a `luminess::Error`) |
| `Builder::directory(dir, "txt")` | `Builder::directory_with_extension(dir, "txt")` |
| `engine.render(name, &view, &mut out)` | `engine.render_into(name, &view, &mut out)` |
| `engine.render_to_string(name, &view)` | `engine.render(name, &view)` |
| `engine.reload(builder)` | `engine.replace(builder.build()?)`, or `engine.reload_dir(dir)` |
| `builder.compile()` and `Engine::new(templates)` | `builder.build()` |
| `engine.templates()`, `Templates`, `engine.swap(templates)` | an `Engine` is the set: `engine.replace(other)`, `engine.contains(name)` |
| `Builder::new(schema)`, `Engine::builder_with(schema)` | `Engine::with_schema(schema)` |
| `Builder::template_with(name, source, schema)` | `Builder::template_with_schema(name, source, schema)` |
| `CompileError`, `RenderError`, `RenderErrorKind` | `Error` and `ErrorKind` (`Compile`, `Io`, `NotFound`, `TooLarge`) |
| `RenderError::template()`, `CompileError::diagnostics()` | `Error::template()`, `Error::diagnostics()` |
| `Shaped` | `HasSchema` |
| `Computed` (`Computed::Value`, `Computed::Text`) | `Answer` (`Answer::Value`, `Answer::Text`) |
| `Failed` | `BlockError` |
| `fn field(&self, id: FieldId)` with `match id.index()` | `fn field(&self, index: usize)` with `match index` |
| `fn call(&self, id: FieldId, args)` | `fn call(&self, index: usize, args)` |
| `Schema::field(name) -> Option<(FieldId, &Kind)>` | `Schema::field(name) -> Option<(usize, &Kind)>` |
| `SchemaRef`, `SchemaBuilder::object(name, impl Into<SchemaRef>)` | `SchemaBuilder::object(name, Schema)`; `Kind::Object(Schema)` |
| `Rendered::is_complete()` | `rendered.failures().is_empty()` |
| `Rendered::first_failure()` | `rendered.failures().first()` |
| `match value { ... }` on `Value`, `Kind`, `Answer` covering every variant | add a `_` arm |
| `items: list(html)` holding `Vec<String>` | `Vec<luminess::Html>` (`Html::from(s)`) |
| a filter or method declared `Kind::Text` that answers `Value::Html` | declare it `Kind::Html` |

Views made with `view!` need no change, except a `list(html)` field, which holds `Vec<Html>`. A view written by hand changes `fn field(&self, id: FieldId)` with `match id.index()` to `fn field(&self, index: usize)` with `match index`.

## Same output, same speed

`equivalence/` checks this release against the published 0.9.3 (random templates, structured templates, and a full page, 4,000 cases each, byte for byte, compile errors included), and the `same_output` fuzz target does the same on any input. The render benchmark matches 0.9.3 within noise. `docs/API.md` now covers every public item with examples, simplest first.
